## 问题 1：workflow 执行时看不到文档内容

**证据** `cli/workflow_runner.py`：

```python
engine.run(analysis_results={}, context=workflow_vars)   # 名义 workflow 与 inline 均如此
```

`analysis_results={}` 导致 custom stage 的 prompt 只能拿到空 `current_results`，
所有 workflow 里的"增强题目"对文档流（PDF/DOCX/EPUB）都是装饰品。

**补丁**：`create_command.py::_run_workflows` 调用处补充上下文：

```python
run_workflows(self.args, context={
    "skill_dir": str(self.skill_dir),          # ExecutionContext 已持有
    "skill_md_path": str(Path(self.skill_dir) / "SKILL.md"),
    "source_files": [str(p.relative_to(self.skill_dir))
                     for p in Path(self.skill_dir).rglob("*.md")],
})
```

`_run_custom_stage` 已支持 `.format(**context)`，无需改动；但题目里的 JSON 花括号
需要双写 `{{ }}`（现有 bundled workflow 未双写，属于潜在 KeyError）。

## 问题 2：增强题目的验证标准是"更大"

**证据** `cli/enhance_skill_local.py`（~L695）：

```
VERIFICATION:
After writing, the file SKILL.md should:
- Be larger than the original (200-1000+ lines)
```

直接驱动 LLM 堆字数：搬运式元数据（文档信息/统计/泛化 When-to-Use）越攒越多。

**补丁**：替换为密度标准（与本仓库 `prompts/deep_distill.md` 的四道铁律一致）：

```
VERIFICATION:
- Every claim traces to [证据: 文件:位置], marked A=stated / B=推断 / C=uncovered
- Decision rules in "condition → action → exception" form replace prose
- SKILL.md ≤ 120 lines (replace, do not append; log deletions in SHRINK_LOG.md)
- Out-of-scope questions must be answered "not covered" (anti-hallucination)
- Include blind-test questions in EVAL.md written from the raw source
```

## 问题 3：PDF 流 SKILL.md 模板是搬运式结构

**证据** `cli/pdf_scraper.py::_generate_skill_md`：硬编码
"Document Information / When to Use（五条泛化 bullet 对所有文档相同）/ Section /
Quick Reference / Statistics / Navigation"，且 description 对任何文档都自没有任何触发词。

**补丁**：
- 保留 Navigation 一处即可（现在 Statistics/Overview/Navigation 三处重复）；
- description 由 LLM 根据首轮内容生成"何时触发/何时不触发"，而不是 `--description` 的原样回写；
- "When to Use" 五条删除，改为空位留给 enhance 阶段填基于原档的具体场景。
