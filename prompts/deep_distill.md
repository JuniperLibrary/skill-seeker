# 深度蒸馏题目（Deep Distillation Prompt）

目标 Skill 目录：{skill_dir}
Skill 名称：{skill_name}
原始素材文件清单：
{source_files}

你是一名知识蒸馏专家。你的任务不是把这份 SKILL.md "变大"，而是把它"变深"。
完成本任务后，一个从未见过原始文档的全新 agent，应当能只靠这个 skill 目录
在真实任务中做出与读过原文档的专家一致的判断。

## 开工契约（先答四问，答不出就停）

按顺序在心里作答并写进 INVENTORY.md 开头（各 ≤2 行），答不出的问题必须显式写"缺"，禁止跳过：

1. **顶尖专家拿到这份文档会做什么？** —— 审源料定切分策略（规则密集/字段表/TOC 可用性）、
   写蒸馏契约（skill 必须能答什么题、必须拒答什么题）、给结论挂证据锚、
   交付前做独立盲考与机器门禁。你的产出要能对着这份清单自证。
2. **顶尖专家从哪些最原始素材入手？** —— 原始文档字节、TOC 目录树、逐页 raw text
   （不是章节摘要）、原始字段表与错误码全表、元数据、以及上游转换器的失败产物
   （单文件 dump 是"哪里失败了"的反面证据）。禁止只吃二手整理稿。
3. **用什么方法和工具？** —— TOC 切分（PyMuPDF get_toc）、页锚 [P#] + grep 检索性测试、
   四阶段管线（盘点→建证→瘦身→自证）、≤120 行瘦身铁律、A/B/C 证据分级。
4. **除你我之外谁证明结果正确？** —— 机器门禁（scripts/verify_skill.py，非人判定）、
   独立盲考官（禁读原文的第三方判卷，≥10 实答题 + 2 反幻觉题）、
   溯源回查（每条规则可在切分文件中 grep 命中）。阶段四的 EVAL.md 必须落到这三件上。

全程遵守四条铁律：
- 铁律1（做深⊥做大）：只能替换与压缩，禁止平铺堆料。SKILL.md 最终 ≤120 行，
  每一段要么是【决策规则】要么是【证据指针】，其余一律删除。
- 铁律2（证据锚定）：每条非显然断言必须标注出处 [证据: 文件名:页码/章节]，
  并区分标记：A=文档明说 / B=合理推断 / C=未覆盖。禁止把推断伪装成文档原意。
- 铁律3（不许编造）：原文没有的写"未覆盖"，不知道的写"不确定"。范围边界必须显式写出。
- 铁律4（先备份）：修改 SKILL.md 前先复制为 SKILL.md.backup，再覆写。

工作分四个阶段，依次完成后才允许进入下一阶段。
每个阶段结束时把产出写进对应文件，写不出来就停下来说明缺什么原始素材。

## 阶段一：盘点原料（不是整理好的材料）

通读上面的原始素材文件清单并打开它们，把素材分成三类，写入 `INVENTORY.md`（≤40行）：
- 【逐字素材】原档里的代码块、命令、SQL、API签名、配置片段（一字不改）、
  表格原始单元格、版本号/日期、修订与勘误、脚注图注、作者给的注意事项和反例
- 【结论性文本】叙述性段落与摘要 —— 只能当作线索，凡是结论都必须回到逐字素材验证
- 【缺失维度】拿不到的一手素材（如 changelog、源码、真实用户报错）逐项列出。
  该维度后续任何结论都只能标 B 或 C。
产出验收：INVENTORY.md 中每个【逐字素材】都带文件与位置号，可被 grep 命中。

## 阶段二：精读原文，建立证据

从【逐字素材】出发提炼领域专属的决策规则，写入 `references/rules.md`：
- 格式：`R#：条件 → 动作 → 例外 [证据: 出处, 引用≤2行原文]`
- 必须主动寻找四类深结构，找不到就写明"原文未给出"：
  1) 边界条件与适用前提　2) 失败模式与反例
  3) 操作顺序/依赖关系　4) "不要做"清单（作者的禁止与警告）
- 与通用能力做差分：模型本来就会的（通用概念解释、常识性套话）一条不许进 references/
验收：每条规则都能沿证据锚回原文；A/B/C 标记齐全。

## 阶段三：重写（替换，不是追加）

用阶段二的成果整体重写 SKILL.md（先做备份），目标结构（≤120行）：
1. frontmatter：description 必须写"何时触发"，含具体触发词，不是泛泛的
   "Use when working with X"
2. 何时用 / 何时不该用：各 3 条以内，可执行的场景描述
3. 核心决策规则表：5-10 条最重要的 R#，直接引用，带证据锚
4. 工作流：遇到什么问题 → 先读本技能哪一节 → 需要深料时打开哪个 references 文件
5. 边界与未覆盖（C 类清单）：把幻觉挡在门外
6. 目录索引：一个文件一句话说明装的是什么深料

同时：
- 把原 SKILL.md 中的纯元数据（文档信息/统计/章节导航等搬运内容）删除或降级为
  references/ 的一行指针
- 若存在机械可执行操作（按格式提取、检索、转换），写进 `scripts/` 一个可运行脚本，
  并在 SKILL.md 工作流中写明如何调用
- 将"删除了哪些内容、为什么"记入 `SHRINK_LOG.md`（这是深度的证明，不是废料）
验收：SKILL.md 行数下降或持平、零通用空话、每条规则带锚。

## 阶段四：自证（拿第三方证据说话）

写入 `EVAL.md`，全部完成后给出最终判定（通过/未通过）：
1. 盲测题集：10 道"只有读完原始文档才能答对"的题 + 2 道范围外题
   （标准答案必须是"未覆盖"，答了具体内容即失败），每题附评分标准
2. 溯源抽查表：从 SKILL.md 与 references/ 随机抽 10 条断言，逐一回原文核对，
   记录 断言/出处/核对结果（一致/偏差/找不到）
3. 机器检查清单：frontmatter 合法、name 与目录一致、description 含触发词、
   所有被指向的文件存在、SKILL.md ≤120 行 —— 逐项打勾
4. 判定与修复：任何一项未过，修复后重验；EVAL.md 必须能被一个独立审核者
   不看原文档也能复核你的核对过程。

最终自检：如果你完成后的产物只是"更大"，没有留下任何一条原文档里没有浅显复述
的决策规则、没有一处证据锚、没有一道盲测题 —— 那就视为失败，回到阶段二重来。
